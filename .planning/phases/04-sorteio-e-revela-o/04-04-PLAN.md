<objective>
Construir a tela de revelação do par (`/draw/:groupId/result`): um cartão fechado que só
mostra o nome de quem o participante tirou e a wishlist dessa pessoa depois de uma ação
deliberada (clique), usando `@defer (on interaction)` para que o conteúdo pesado realmente
não exista no DOM antes do clique (D-06). A busca é uma única query com join embedado e FK
nomeada (D-07), carregada por um resolver funcional (D-08, ID18) que também trata os
estados "ainda não sorteado" e "sem resultado" em PT-BR, sem erro genérico.

Purpose: esta é a segunda metade do core value, ao lado da Fase 4 inteira — provar que
cada participante vê exatamente o próprio par, nunca o de outra pessoa, através de uma
ação explícita e não de um carregamento automático. DRAW-08 e DRAW-09 só existem quando
esta tela existe; sem ela, o sorteio roda mas ninguém descobre quem tirou.
Output: `features/draw/result/draw-result.page.{ts,html}`, `drawResultResolver`,
`DrawService.getMyResult()`, contrato `Draw`/`DrawResult` em `group.model.ts`, rota nova em
`app.routes.ts`, `docs/sdd.md` atualizado.

```typescript
  /**
   * D-07/DRAW-09: busca o par do usuário logado com nome e wishlist de quem ele tirou,
   * numa única query com join embedado. A FK é nomeada EXPLICITAMENTE
   * (`participant!draw_receiver_id_fkey`) porque `draw` tem DUAS foreign keys para
   * `participant` (giver_id e receiver_id) — `participant(...)` sozinho é ambíguo e o
   * supabase-js recusa a query.
   *
   * `.eq('group_id', groupId)` é redundante com a RLS (a policy de `draw` já restringe
   * a `giver_id in (select private.my_participant_ids())`), mas mantém a intenção
   * explícita e permite `.maybeSingle()` resolver corretamente quando o usuário está em
   * vários grupos — mesmo estilo de `updateWishList()` em `GroupService`.
   *
   * DRAW-10 não é tocado aqui: a privacidade vem inteiramente da policy de SELECT em
   * `draw` (0003_rls_policies.sql) — nunca adicionar um filtro extra "escondendo" o
   * próprio par do admin, isso já é garantido pelo banco.
   */
  async getMyResult(groupId: string): Promise<{ result: DrawResult | null; error: string | null }> {
    const { data, error } = await this.supabase
      .from('draw')
      .select('id, receiver:participant!draw_receiver_id_fkey(display_name, wish_list)')
      .eq('group_id', groupId)
      .maybeSingle();
    if (error) {
      return { result: null, error: 'Não foi possível carregar seu resultado.' };
    }
    return { result: (data as DrawResult | null), error: null };
  }
```

```typescript
import { inject } from '@angular/core';
import { Router, type ResolveFn, type UrlTree } from '@angular/router';
import type { DrawResult } from '../models/group.model';
import { DrawService } from '../services/draw.service';
import { GroupService } from '../services/group.service';

/**
 * Estado resolvido para `/draw/:groupId/result` (D-08, ID18). Um discriminated union em
 * vez de só `DrawResult | null` porque a TELA precisa diferenciar "ainda não sorteou" de
 * "sorteou mas não achou resultado" — são duas mensagens PT-BR diferentes, não um erro.
 */
export type DrawResultState =
  | { status: 'ready'; result: DrawResult }
  | { status: 'not-drawn' }
  | { status: 'missing' };

/**
 * Resolver funcional de `/draw/:groupId/result` (RA5-ID18, D-08). O `memberGuard`
 * (`canActivate`) já roda ANTES na mesma rota e barra quem não é membro — este resolver
 * só carrega o par, nunca reimplementa a checagem de acesso (mesma separação de
 * responsabilidades que `admin.guard.ts`/`group.resolver.ts` já estabeleceram na Fase 3:
 * um `UrlTree` devolvido por um `ResolveFn` não redireciona, só vira `route.data`).
 *
 * Por que checar `group.status` ANTES de chamar `getMyResult()`: antes do sorteio não
 * existe linha de `draw` para ninguém — consultar `draw` primeiro devolveria sempre
 * `null` e obrigaria a tela a adivinhar o motivo. Checar o status primeiro permite a
 * mensagem certa ("o sorteio ainda não aconteceu") sem uma segunda query desnecessária.
 */
export const drawResultResolver: ResolveFn<DrawResultState | UrlTree> = async (route) => {
  const groups = inject(GroupService);
  const draw = inject(DrawService);
  const router = inject(Router);

  const groupId = route.paramMap.get('groupId');
  if (!groupId) {
    return router.createUrlTree(['/dashboard']);
  }

  const { group } = await groups.loadGroup(groupId);
  if (!group) {
    return router.createUrlTree(['/dashboard']);
  }

  if (group.status !== 'closed') {
    return { status: 'not-drawn' };
  }

  const { result } = await draw.getMyResult(groupId);
  if (!result) {
    return { status: 'missing' };
  }

  return { status: 'ready', result };
};
```
