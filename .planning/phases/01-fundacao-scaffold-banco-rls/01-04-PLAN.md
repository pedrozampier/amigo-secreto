**Parte A — `vercel.json`.**

Ler o caminho de saída real no SUMMARY da plan 01-03 (algo como `dist/amigo-secreto/browser`) e
usar esse valor literal. Criar `vercel.json`:

```json
{
  "buildCommand": "npm run build",
  "outputDirectory": "dist/<NOME_REAL_DO_PROJETO>/browser",
  "rewrites": [
    { "source": "/(.*)", "destination": "/index.html" }
  ]
}
```

O bloco `rewrites` **não é opcional**, mesmo que o auto-detect da Vercel acerte o
`outputDirectory`: sem ele, abrir `/join/<token>` ou `/dashboard` direto na URL de produção dá
404, porque a Vercel procura um arquivo estático nesse caminho e o Angular Router nunca é
carregado. O auto-detect da Vercel não tem como inferir isso do `angular.json` (Pitfall 12).

**Parte B — `scripts/generate-env.js`.**

O Angular resolve `environment.prod.ts` em tempo de **build**; não existe mecanismo nativo de
ler `process.env` no browser depois. O padrão é um hook `prebuild` que escreve o arquivo a
partir das env vars da Vercel:

```js
// scripts/generate-env.js
// Gera src/environments/environment.prod.ts a partir das variáveis de ambiente
// no momento do build (Vercel -> Project Settings -> Environment Variables).
// Este arquivo NUNCA é commitado — está no .gitignore (ver plan 01-03).
const fs = require('node:fs');
const path = require('node:path');

const url = process.env.SUPABASE_URL;
const key = process.env.SUPABASE_PUBLISHABLE_KEY;

if (!url || !key) {
  console.error(
    '[generate-env] SUPABASE_URL e SUPABASE_PUBLISHABLE_KEY precisam estar definidas. ' +
      'Localmente: copie src/environments/environment.example.ts para environment.ts. ' +
      'Na Vercel: Project Settings -> Environment Variables.',
  );
  process.exit(1);
}

// Guarda de segurança (DB-11): a chave secreta jamais pode entrar no bundle do cliente.
if (/^sb_secret_/.test(key) || /service_role/i.test(key)) {
  console.error('[generate-env] ABORTADO: a chave fornecida é uma SECRET key. Use a chave publicável.');
  process.exit(1);
}

const content = `// GERADO AUTOMATICAMENTE por scripts/generate-env.js — não editar nem commitar.
export const environment = {
  production: true,
  supabaseUrl: '${url}',
  supabasePublishableKey: '${key}',
};
`;

const out = path.join('src', 'environments', 'environment.prod.ts');
fs.mkdirSync(path.dirname(out), { recursive: true });
fs.writeFileSync(out, content);
console.log('[generate-env] escrito', out);
```

A guarda de regex é deliberada: transforma "não cole a secret key" de convenção em falha de
build.

Adicionar ao `package.json`:
```json
"prebuild": "node scripts/generate-env.js"
```
O npm roda `prebuild` automaticamente antes de `build` — nenhuma configuração extra é
necessária na Vercel.

Confirmar no `angular.json` que a configuração `production` tem o `fileReplacements` que troca
`environment.ts` por `environment.prod.ts`; se o `ng new` da v21 não gerou esse bloco, adicioná-lo
ao target `build` -> `configurations` -> `production`:
```json
"fileReplacements": [
  { "replace": "src/environments/environment.ts", "with": "src/environments/environment.prod.ts" }
]
```

**Parte C — `.github/workflows/ci.yml`.**

ENG-06 exige integração por PR; um gate de CI é o que dá dentes a isso. O grep de secrets tem
que rodar contra `dist/` **depois** do build, porque é o `dist/` que vai para o browser.

```yaml
name: CI

on:
  pull_request:
    branches: [develop, main]
  push:
    branches: [develop, main]

jobs:
  qualidade:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: '22'
          cache: npm
      - run: npm ci --legacy-peer-deps

      - name: Lint (ENG-01/ENG-04) — falha com qualquer warning
        run: npx eslint src --max-warnings=0

      - name: Estado em Signals, nunca RxJS (ID9 — sem regra de lint equivalente)
        run: npm run check:no-rxjs-state

      - name: Nenhuma secret key no código-fonte (DB-11, lado source)
        run: |
          if grep -rEi 'service_role|sb_secret_|SERVICE_ROLE' src/; then
            echo "::error::Secret key encontrada no código-fonte"
            exit 1
          fi
          echo "fonte limpa"

      - name: Build de produção
        env:
          SUPABASE_URL: ${{ secrets.SUPABASE_URL }}
          SUPABASE_PUBLISHABLE_KEY: ${{ secrets.SUPABASE_PUBLISHABLE_KEY }}
        run: npm run build

      - name: Nenhuma secret key no bundle (DB-11, lado bundle)
        run: |
          if grep -rEi 'service_role|sb_secret_' dist/; then
            echo "::error::VAZAMENTO: secret key no bundle de produção — bloquear deploy"
            exit 1
          fi
          echo "bundle limpo"

      - name: Nenhum NgModule (RA2-ID3)
        run: |
          if [ -n "$(find src -iname '*.module.ts')" ]; then
            echo "::error::Arquivo *.module.ts encontrado"
            exit 1
          fi
          echo "zero NgModule"

      - name: Testes unitários
        run: npm test -- --run
```

Cadastrar os dois secrets do repo para o job de build funcionar:
```bash
gh secret set SUPABASE_URL --body "<valor do SUMMARY da plan 01-01>"
gh secret set SUPABASE_PUBLISHABLE_KEY --body "<chave publicável>"
```
Se `npm test -- --run` falhar porque o scaffold não tem nenhum teste, ajustar para
`npm test -- --run --passWithNoTests` (os testes reais são ENG-02/03, Fase 4).
